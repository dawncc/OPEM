# Industry patterns for Python compression backends

## Pattern comparison

| Pattern | Backend behavior | Prompt/rules role | Strength | Main risk |
| --- | --- | --- | --- | --- |
| Sliding trim | Keep the newest token-bounded messages | Rules only | Cheap and deterministic | Loses early constraints |
| Selective clearing | Remove old tool results or reasoning blocks by type | Rules and exclusions | High savings for tool-heavy agents | Removes evidence needed later |
| Rolling LLM summary | Summarize evicted turns and combine with recent messages | Separate initial/update/final prompts | Readable and compact | Recursive drift |
| Extractive compression | Rank and quote source sentences or lines | Rules, scoring, budgets | Auditable and low cost | Weak semantic synthesis |
| Provider compaction | Send history to a provider compaction endpoint | Provider-managed instructions | Simple integration | Opaque and provider-bound |
| Tiered hybrid | Pin invariants, clear bulk data, retrieve memory, summarize eligible text | Rules define eligibility; prompt performs synthesis | Best balance for long agents | More state and evaluation complexity |

## Official implementation signals

- OpenAI exposes a Responses compaction item generated by `v1/responses/compact`. Treat it as provider-native derived state, not the only archive.
- LangGraph documents trimming, deletion, summarization, checkpointing, and custom filtering as separate strategies.
- LangMem's `SummarizationNode` has distinct initial-summary, existing-summary-update, and final-composition prompts. It tracks summarized message IDs and a running summary. Bind the summarizer model's output-token limit explicitly; its summary budget is otherwise an accounting limit rather than an enforced generation limit.
- Anthropic context editing clears old tool results and reasoning blocks server-side using configurable trigger, keep, minimum-clear, and tool-exclusion rules. The client retains the full unmodified history. Its guidance recommends clearing enough content to justify invalidating the prompt cache.
- Google's agent architecture guidance separates working context, session history, long-term memory, and artifacts. It describes overlapping-window LLM compaction and keeping large artifacts out of the prompt until requested.

## Recommended Python modules

Keep policy, prompt construction, model invocation, validation, and persistence separate:

```text
compression/
  policy.py       # thresholds, protected classes, priorities, watermarks
  selector.py     # turn grouping, tool clearing, relevance and token budgets
  prompts.py      # versioned initial/update/rebuild prompt builders
  schemas.py      # summary snapshot and source-reference models
  summarizer.py   # provider adapter and structured-output parsing
  validator.py    # exact-fact and protected-item gates
  service.py      # orchestration, fallback, metrics and persistence
```

The orchestration should be:

```text
count -> trigger -> classify/pin -> clear deterministic bulk -> select evicted turns
      -> optionally summarize -> validate -> compose working context -> persist snapshot/report
```

Run deterministic reduction before an LLM call. Only summarize natural-language material whose expected reuse savings exceed summarization cost. Keep current instructions and protected evidence outside the summarizer prompt and insert them verbatim into the final working context.

## Three prompt modes

Use different builders instead of one universal prompt:

1. `initial`: generate a structured summary from original evicted turns.
2. `update`: merge a previous snapshot with only newly evicted turns; preserve source IDs and conflicts.
3. `rebuild`: periodically regenerate from original archived sources to measure and repair drift.

Version prompt templates and policy independently. Store `prompt_version`, `policy_version`, source sequence range, summarized message IDs, model, token counts, validation results, and creation time with each snapshot.

## Rules worth making configurable

- `trigger_tokens` and target low watermark;
- reserved output and safety margin;
- complete recent turns to retain;
- per-role and per-tool budgets;
- protected roles, tools, tags, and regex fact classes;
- minimum tokens cleared per compaction;
- initial/update/rebuild model and temperature;
- summary output budget;
- rebuild interval and maximum recursive update count;
- exact-fact validation and fallback mode.

Do not make safety invariants editable from an ordinary web form. The page may expose operational thresholds and preview the resulting policy, while protected classes, injection handling, archive retention, and validation gates remain server-controlled.
